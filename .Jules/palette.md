## 2024-05-24 - Accessibility labels on SwiftUI Icon Buttons
**Learning:** `.help(...)` and `.accessibilityLabel(...)` are different accessibility channels. Per Apple's documentation, `.help(...)` configures the view's *accessibility hint* and its help tag (the tooltip) on macOS — it does **not** set the accessibility *label*. VoiceOver announces the label as the element's identity; hints are supplementary and only spoken when the user enables hint verbosity. An icon-only button with only `.help(...)` therefore has no label — VoiceOver reads it as just "button". An earlier entry in this file claimed `.help` automatically became the label; that was incorrect and is superseded here. (The action in the "Add explicit accessibility labels" commit was right; only its reasoning — that tooltips are never read — was imprecise: they feed the hint channel, not the label.)
**Action:** Always pair `.help(...)` with `.accessibilityLabel(...)` on icon-only buttons, mirroring the tooltip string. That guarantees both the hover tooltip and a real VoiceOver label at zero cost. Use a different label string only when the announcement should differ from the tooltip.
